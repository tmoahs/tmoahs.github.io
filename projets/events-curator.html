AI Cultural Events Curator

Un utilisateur décrit ses goûts, et reçoit dans sa boîte mail cinq événements culturels réels de sa ville — chacun avec une description écrite pour lui. Le tout tourne sans aucune infrastructure payante.

n8n LLM APIs Google Gemini Ticketmaster API Gmail API REST APIs Automatisation

Le problème

Trouver une sortie culturelle qui corresponde vraiment à ses goûts demande du temps : on ouvre plusieurs sites, on recoupe les annonces, on retombe sur les mêmes événements, et on manque d'informations pour se décider. Les recommandations proposées sont soit génériques, soit noyées dans du bruit.

L'objectif était donc double : une recommandation réellement personnalisée, et un coût d'exploitation nul. La contrainte de coût n'était pas un détail — c'est elle qui a structuré toutes les décisions techniques.

La démarche

  1. Partir du besoin, pas de la technique Un formulaire minimal — ville, catégorie, style artistique — sans compte à créer ni application à installer. Le workflow est auto-porté par n8n, donc aucun front-end à maintenir.
  2. Récupérer de vraies données, pas des données inventées Interrogation de l'API Ticketmaster pour obtenir 20 événements réels, avec leurs visuels, lieux, dates et liens officiels.
  3. Dédupliquer pour garantir la variété Sur 20 résultats, beaucoup se répètent ou se ressemblent. Un filtrage ramène l'ensemble à 5 événements réellement distincts — sinon l'email perd tout intérêt.
  4. Faire appel à l'IA sans exploser le budget C'est la décision structurante du projet : plutôt que d'appeler Google Gemini une fois par événement (5 appels), toutes les données sont agrégées et envoyées en un seul appel qui génère les 5 descriptions. C'est ce qui permet de rester dans le palier gratuit.
  5. Soigner la sortie Construction d'un email HTML lisible partout, avec CSS en ligne (imposé par Gmail), image, lieu, adresse, dates et lien direct vers chaque événement.
  6. Livrer Envoi via l'API Gmail. L'utilisateur n'a rien à faire : le résultat arrive dans sa boîte mail.

Le résultat tient dans une contrainte : une génération de texte par IA coûte normalement un appel par contenu. En regroupant les cinq événements dans un seul prompt, le projet reste gratuit à l'usage — sans dégrader la personnalisation, puisque le modèle reçoit le style artistique demandé par l'utilisateur.

Ce que j'en retiens

  • Le coût est une décision de conception, pas une réflexion après coup. Concevoir le prompt en fonction du palier gratuit a changé l'architecture du workflow, pas seulement la facture.
  • La qualité des données d'entrée fait la qualité de la sortie. Sans l'étape de déduplication, l'IA aurait rédigé avec soin cinq descriptions du même concert.
  • Un bon projet documente aussi ses limites. Savoir dire ce qui ne marche pas encore est plus crédible que de prétendre que tout est parfait.

Limites connues et pistes

  • Ticketmaster est une plateforme orientée concerts : les expositions y sont sous-représentées. L'intégration de l'API Eventbrite comme seconde source est la prochaine étape.
  • La déduplication se base sur le titre : un spectacle à l'affiche plusieurs jours peut encore apparaître deux fois.
  • Gemini produit parfois une description générique sur un événement peu documenté. Piste : scinder le workflow en deux appels — un pour la recherche d'informations factuelles, un pour la rédaction personnalisée.
